# Кишинів Гід / Кишинёв Гид / Ghidul Chișinăului

Локальний lifestyle-гід по Кишиневу трьома мовами (українська, російська,
румунська): кафе, місця для роботи з ноутбуком, тихі локації, прогулянки,
активності та афіша подій.

React 19 · TypeScript · Vite 6 · Tailwind CSS 4 · Leaflet · localStorage.

## Запуск

**Потрібен Node.js 20+.**

```bash
npm install
npm run dev        # http://localhost:3000
```

Інші команди:

```bash
npm run typecheck  # tsc --noEmit
npm test           # 102 юніт-тести (tests/*.test.ts)
npm run verify     # typecheck + тести + збірка, одним заходом
npm run seo:files  # згенерувати public/sitemap.xml і public/robots.txt з каталогу
npm run build      # seo:files + vite build → dist/
npm run preview    # локальний перегляд зібраного dist/
```

Тести без залежностей — просто `tsx`, який запускає файли й порівнює значення.

## Структура URL

Застосунок використовує History API (`src/router.ts`), без hash-роутингу.
Старі посилання виду `#category=cafes` та `#place=slug` автоматично
переписуються на нові шляхи під час завантаження.

| Шлях | Сторінка |
| --- | --- |
| `/` | Головна: hero, «Куди піти сьогодні?», рекомендовані та популярні |
| `/remote-work` `/quiet-places` `/cafes` `/food` `/walks` `/activities` | Категорії |
| `/<category>/<slug>` | Сторінка місця (модальне вікно над стрічкою категорії) |
| `/events` | Афіша з фільтрами «сьогодні / завтра / вихідні / тиждень» |
| `/map` | Карта Кишинева |
| `/favorites` | Обране (`noindex`) |
| `/privacy` | Політика конфіденційності |
| `/contacts` | Контакти — email і форма «Додай своє улюблене місце» |
| `/admin` | Адмін-панель (`noindex`, не показується в публічній навігації) |

Пошук зберігається в URL як `?q=`, тому результати можна надіслати посиланням.

### Мови

Українська віддається з кореня, російська та румунська — з префіксом:

```
/cafes        /ru/cafes        /ro/cafes
/remote-work/tucano-coffee-brasil   /ru/remote-work/…   /ro/remote-work/…
```

`/uk/...` працює як псевдонім кореня. Перемикач мов у шапці залишає користувача
на тій самій сторінці і запам'ятовує вибір: якщо людина колись обрала румунську,
наступний захід на голий `/` відкриє `/ro`. Автовизначення за мовою браузера
навмисно не робиться — `/` завжди українська для нових відвідувачів і для
пошукових роботів, тому canonical лишається передбачуваним.

Кожна сторінка публікує `hreflang` для всіх трьох мов плюс `x-default`,
`<html lang>` і `og:locale`; `sitemap.xml` містить усі три версії кожного URL
із взаємними `xhtml:link`.

### Публікація на Cloudflare Pages

Сайт — статика з реальними шляхами (`/cafes`, `/ro/map`), тож сервер має
віддавати `index.html` на будь-який маршрут. Cloudflare Pages розуміє
Netlify-формат `public/_redirects` і `public/_headers` без змін — обидва файли
потрапляють у `dist` під час збірки й підхоплюються автоматично.

**Через Git (рекомендовано):**

1. Workers & Pages → Create → Pages → Connect to Git → обрати репозиторій.
2. Build command: `npm run build`. Build output directory: `dist`.
3. Environment variables (Settings → Environment variables), для продакшн-оточення:
   * `VITE_SITE_URL` = `https://chisinau-guide.com`
   * `SITE_URL` = `https://chisinau-guide.com`
   * `VITE_FORMSPREE_ENDPOINT` = ваш endpoint з [formspree.io](https://formspree.io)
   * `GEMINI_API_KEY` = ваш ключ із [aistudio.google.com](https://aistudio.google.com/apikey) —
     додавайте з позначкою **Encrypt**, це секрет (див. «AI-підбір місць» нижче)
   * `NODE_VERSION` = `24`
   * `VITE_ENABLE_ADMIN` — **не задавати**: без нього маршрут `/admin`
     у публічній збірці не реєструється.
4. Кастомний домен — Custom domains → додати `chisinau-guide.com`, Cloudflare
   сам виставить DNS/SSL, якщо домен уже є в тому самому Cloudflare-акаунті.

**Через drag-and-drop** — зібрати локально (`npm run build`) і перетягнути
теку `dist` у Workers & Pages → Create → Pages → Upload assets. Змінні
середовища тоді задаються постфактум у Settings, і кожен реліз доведеться
заливати вручну.

### Форма «Додай своє улюблене місце»

Бекенду немає, тому заявки приймає **[Formspree](https://formspree.io)** —
безкоштовний хостований прийомник форм. Працює це так:

1. Зареєструватися на formspree.io, створити форму, скопіювати її endpoint
   (`https://formspree.io/f/xxxxxxxx`).
2. Покласти його у змінну середовища `VITE_FORMSPREE_ENDPOINT` (див.
   `.env.example`) — і локально в `.env.local`, і на Cloudflare Pages.
3. `AddPlaceForm.tsx` надсилає `FormData` напряму на цей endpoint; Formspree
   пересилає заявку на пошту, привʼязану до акаунту.

Endpoint — не секрет (він публічний, потрапляє в клієнтський бандл), тож
нести його в `.env.local`/dashboard-змінні можна без побоювань. Поля форми:
`place-name`, `place-address`, `place-category`, `place-why`, `contact-email`
і пастка для ботів `_gotcha` (конвенція Formspree — заявку з заповненим полем
відкидають мовчки).

Якщо `VITE_FORMSPREE_ENDPOINT` не задано — форма навіть не намагається
надіслати запит і одразу показує помилку з поясненням, а не вдає успіх.

### AI-підбір місць

На головній сторінці є поле, де відвідувач своїми словами описує, чого хоче
(«хочу погуляти з дитиною сьогодні ввечері») — AI підбирає відповідні місця
з каталогу. Працює це так:

1. `src/components/AiPlanner.tsx` шле запит на `/api/recommend`.
2. `functions/api/recommend.ts` — **Cloudflare Pages Function**: окрема
   серверна функція (не частина React-бандла), яка звертається до
   [Gemini API](https://aistudio.google.com) з каталогом місць і просить
   модель підібрати відповідні `slug`-и, вимагаючи відповідь у вигляді JSON за
   фіксованою схемою (`responseSchema`) — тому відповідь завжди має очікувану
   форму, а не "сподіваємось, що це правильний JSON".
3. Ключ API (`GEMINI_API_KEY`) лишається на сервері — на відміну від
   `VITE_*`-змінних, він **ніколи** не потрапляє в клієнтський бандл. Задається
   лише в Cloudflare → Settings → Environment variables, з позначкою
   **Encrypt** (див. `.env.example`).
4. Модель бачить лише каталог, який уже є на сайті, і їй прямо заборонено
   вигадувати місця, яких там немає — та сама «правило чесності», що й для
   решти каталогу.
5. Модель — `gemini-3.5-flash-lite`: найдешевший/найшвидший рівень Gemini,
   достатній для підбору зі списку; каталог надсилається в скороченому
   вигляді (коротші ключі, обрізані описи), щоб менше платити за вхідні
   токени на кожен запит.

Без заданого `GEMINI_API_KEY` функція повертає `503` і форма чесно показує
помилку, а не вдає, що підбір спрацював. Це платний API (є й безкоштовна
квота — див. [ai.google.dev/pricing](https://ai.google.dev/gemini-api/docs/pricing))
— функція сама по собі не обмежує частоту запитів; якщо з'явиться
зловживання, варто додати Cloudflare Rate Limiting Rules або Turnstile
окремо.

## Дані

Каталог живе у `src/data/chisinauPlaces.ts`, таксономія (категорії, сценарії,
типи кухонь, атмосфери) — у `src/data/taxonomy.ts`. Місця та події
зберігаються в localStorage (`chisinau_places_v3`, `chisinau_events_v3`), обране —
у `chisinau_favorites_v1`, обрана мова — у `chisinau_locale`.

Переклади контенту лежать на самому записі, у полі `i18n`:

```ts
{
  name: 'Парк Дендрарій (Parcul Dendrariu)',   // українська — базові поля
  i18n: {
    ru: { name: 'Парк Дендрарий (Parcul Dendrariu)', description: '…' },
    ro: { name: 'Parcul Dendrariu', description: '…' },
  },
}
```

Незаповнене поле показується українською, тож частково перекладений каталог
читається коректно. Редагувати переклади можна прямо в адмін-панелі — у формах
місця й події є блок «Переклади».

Сам рядок `opening_hours` зберігається українською (його читає парсер), але
в інтерфейсі він перебудовується мовою читача: `Цілодобово 24/7` →
`Non-stop 24/7`, `10:00 – 18:00 (Вихідний: Пт)` → `10:00 – 18:00 (Închis: Vi)`.

### Коментарі

Кожна сторінка місця має блок коментарів: імʼя (необовʼязкове), текст до 600
символів, видалення власного запису. **Бекенду в проєкті немає**, тому
коментарі зберігаються в localStorage і видимі лише їхньому автору — блок
прямо про це попереджає, щоб ніхто не думав, що пише для інших читачів.

Уся робота зі сховищем ізольована в `src/utils/comments.ts` — чотири функції
(`getComments`, `getCommentCount`, `addComment`, `deleteComment`). Жоден
компонент не звертається до localStorage напряму, тож підключення реального
API — це переписати цей один файл і зробити виклики асинхронними.

Щоб коментарі стали справжніми, потрібні три речі, яких у статичному SPA бути
не може: сервер зі сховищем, автентифікація (інакше неможливо відрізнити
авторів) і модерація.

### Оновлення каталогу в існуючих браузерів

`getStoredPlaces()` не просто читає localStorage, а **звіряє** збережене
з тим, що є в `chisinauPlaces.ts`:

* записи, змінені в адмінці, лишаються як є;
* решта відомих записів оновлюється з каталогу — тому виправлення описів,
  графіків і перекладів доходять до тих, хто вже відкривав сайт;
* нові записи каталогу дописуються.

Без цього перший візит назавжди заморозив би каталог у тому браузері.
Змінені й видалені в адмінці id зберігаються окремо (`chisinau_edited_v1`,
`chisinau_deleted_v1`) — інакше злиття або затирало б правки, або повертало б
видалене назад.

### Чому не Google Maps

Дані беруться з OpenStreetMap, а не з Google Maps, і це не технічна перевага,
а ліцензія. **Google Maps Platform Terms §3.2.3** забороняють кешувати й
зберігати контент Places API: дозволено тримати лише `place_id`, решту — не
довше 30 днів. Постійний каталог назв, адрес, координат і графіків під ці
умови не підпадає. ODbL, під якою поширюється OpenStreetMap, навпаки прямо
дозволяє зберігання й поширення за умови атрибуції — вона реалізована через
поле `source`.

### Походження даних і правило чесності

Каталог містить **117 реальних місць**. Назва, адреса й координати кожного —
з [OpenStreetMap](https://www.openstreetmap.org/copyright) (ODbL); поле `source`
рендериться в картці як атрибуція.

Головне правило: **невідоме не показується як факт**. Тому в `Place` більшість
полів опційні, а `confirmed.fields` перелічує те, що справді перевірено:

```ts
{
  wifi: true,                                   // тег internet_access в OSM
  terrace: undefined,                           // ніхто не перевіряв
  confirmed: { fields: ['address', 'coordinates', 'opening_hours', 'wifi'] },
}
```

`undefined` («не перевіряли») і `false` («перевірили, немає») — різні стани, і
UI їх не змішує. Щоб компілятор це контролював, увімкнено `strictNullChecks`.

Що є зараз:

| Поле | Підтверджено |
| --- | --- |
| адреса, координати | 117 |
| графік роботи | 60 |
| сайт | 49 |
| Wi-Fi | 29 |
| безкоштовний вхід | 34 |
| тераса | 9 |
| кондиціонер | 2 |

Чого **немає навмисно**: оцінок 1–5 (жодної не міряли), телефонів (у OSM їх
немає, вигадувати не можна).

Подій — 8, усі реальні (джерело — офіційний календар visit.chisinau.md,
організатори та профільна преса, звірено станом на 23.09.2026); вигаданих
демо-подій каталог не містить. Список варто періодично звіряти й оновлювати —
події застарівають.

### Зображення

Фотографій самих закладів і подій немає. Замість порожніх карток показується
**тематична ілюстрація** за категорією або типом (`utils/illustrations.ts`),
завжди з підписом «Ілюстративне фото» — без підпису стокове фото чужого кафе
читалося б як фото цього закладу. Підбір для місць детермінований (хеш від
slug), тож місце завжди має те саме зображення. Щойно у `place.photos`
зʼявиться справжнє фото, воно замінює ілюстрацію, і підпис зникає. Для подій
такого перемикання поки немає — картка завжди показує ілюстрацію з підписом.

### Адмін-панель і публікація змін

Справжньої авторизації без бекенду бути не може, тому її й не імітовано.
Маршрут `/admin` реєструється **лише** за `VITE_ENABLE_ADMIN=true`, і цей
прапорець має жити у `.env.development.local`, а **не** в `.env.local`:
Vite читає `.env.local` у всіх режимах, зокрема в production, тож звідти він
потрапив би на живий сайт. Сам компонент вантажиться окремим чанком — у
публічній збірці його коду немає взагалі, навіть якщо прапорець увімкнути
випадково.

Локальний запуск:

```bash
npm run dev            # → http://localhost:3000/admin
```

**Як опублікувати зміни.** Адмінка пише в localStorage — це сховище вашого
браузера, не сервер, тож самі по собі правки на сайт не потраплять. Цикл такий:

1. Відредагували місця й події в адмінці.
2. Натиснули **«Вивантажити каталог»** — завантажиться `chisinauPlaces.ts`.
3. Поклали цей файл у `src/data/` замість старого.
4. `npm run build` і задеплоїли (push у гілку, привʼязану до Cloudflare
   Pages, або вручну через drag-and-drop).

Експорт використовує `JSON.stringify`, тому рядки екрануються правильно, а
поля зі значенням `undefined` зникають — саме та семантика, яка потрібна
каталогу («ніхто не перевіряв», а не «немає»). `tests/exportCatalogue.test.ts`
перевіряє round-trip: згенерований файл імпортується назад і має збігатися
з вихідними даними до байта.

Мікророзмітка навмисно не публікує `aggregateRating`: відгуків у проєкті немає,
а вигадані оцінки — це неправдиві структуровані дані.

#### Оцінки в категорії «Віддалена робота»

Для дев'яти місць цієї категорії Wi-Fi спирається на тег `internet_access`
в OpenStreetMap — це єдина характеристика з зовнішнім джерелом. Розетки, тиша
й комфорт в OSM відсутні, тому в реальних записів вони стоять на нейтральних 3.
Це свідомо: такі місця **не потрапляють** у фільтри «Багато розеток (4+)» та
«Тихо (4+)», доки хтось не звірить їх на місці. `work_rating` виводиться
з тривалості робочого дня: 4 для закладів, відкритих 14+ годин, інакше 3.

Графік роботи парситься з рядка `opening_hours`. Підтримуються формати
`08:00 – 22:00`, `Цілодобово 24/7`, `12:00 – 24:00` (через північ),
`10:00 – 18:00 (Вихідний: Пт)`, `09:00 – 19:00 (Пн-Сб)` і OSM-стиль `Mo-Fr 09:00-20:00`.
Якщо рядок не розпізнано, місце показує «Графік уточнюється», а не «Зачинено».

```
    search.ts            Пошук за наміром: «кава» → кафе, «ноутбук» → робота
    openingHours.ts      Розбір графіка роботи, «відчинено зараз»

```

## Як додати ще одну мову

1. Додати код у `LOCALES` і `LOCALE_META` (`src/i18n/types.ts`).
2. Створити `src/i18n/dictionaries/<code>.ts` за формою `Dictionary` з `uk.ts` —
   TypeScript не дасть пропустити жоден ключ.
3. Зареєструвати словник у `DICTIONARIES` (`src/i18n/index.tsx`).

Компоненти чіпати не треба: `taxonomy.ts` не містить тексту, а роутер, hreflang,
sitemap і robots будуються зі списку `LOCALES`.

## Що можна додати далі

Архітектура готова до авторизації, відгуків і персоналізації: дані читаються
через `utils/storage.ts` (легко замінити на API), фільтрація й пошук —
чисті функції без React, роутер повертає типізований `Route`.
